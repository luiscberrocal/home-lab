Homelab Network Design

A segmented home network with a 4-bay NAS at the center. You reach it from anywhere over Tailscale, and clients reach a few published apps through Cloudflare Tunnel. Either way, the router has no open ports. It gets built in five phases, so each step works on its own before the next one starts.

The one blocker: the Deco M5 can't tag VLANs or map Wi-Fi networks to VLANs. Its "guest network" is the only isolation it offers. Segmenting IoT and cameras properly needs a new router, a managed switch and access points (Phase 2 and 3). Until then, the NAS and Tailscale work fine on the existing network.
Topology

How it fits together

Everything plugs into one managed switch. The gateway routes between VLANs and enforces the firewall rules. Nothing comes in through the router. Your own devices join a Tailscale tunnel that ends at the NAS. Clients reach the published apps at Cloudflare, which forwards the traffic down a tunnel the Linux box opened.

Network segments

Seven VLANs, one job each

The VLAN ID matches the third octet of the subnet, so you can tell a device's VLAN from its IP. The design uses 10.0.x.0/24 instead of 192.168.1.x. Hotel and café networks use 192.168.x almost everywhere, and an address clash there breaks remote access.

IoT gets a 2.4 GHz-friendly SSID (WPA2, no band steering), because many cheap devices can't join WPA3 or 5 GHz networks. Keep the number of SSIDs at four or fewer. Each extra SSID costs airtime.

Firewall rules

Who can talk to whom

The default between VLANs is block. Every arrow below is an explicit allow rule on the gateway. Replies to allowed connections ("established/related") always pass, so a trusted laptop can open a camera stream without the camera being able to start a connection back.

  • IoT → Servers is limited to Home Assistant (8123) and MQTT (1883). It lets devices push state without being able to reach the NAS file shares.
  • Servers → Cameras lets Frigate pull the RTSP video streams (554). The cameras never talk to the internet. That blocks the "phone home" cloud features many cheap cameras ship with.
  • DMZ → anything at home is blocked, apart from DNS. The Linux box is the one machine strangers' traffic reaches, so if an app on it is ever compromised, the attacker is stuck in the DMZ. The NAS pulls backups from it (Servers → DMZ, SSH 22), so the Linux box never holds credentials for the NAS.
  • Trusted → Cameras is for the cameras' own web pages during setup. Day to day you watch video through Frigate or Home Assistant instead.
  • DNS: every VLAN may reach AdGuard Home on the NAS on port 53. Block outbound port 53 to anywhere else, so IoT devices can't bypass it with hard-coded DNS servers.
  • Casting and AirPlay: turn on the gateway's mDNS reflector between Trusted and IoT, so your phone still finds the TV and speakers.
Remote access

Tailscale, with nothing exposed

Tailscale builds an encrypted WireGuard mesh between your devices. Connections go out from your home, so the router needs no port forwards, and it still works if your ISP puts you behind carrier-grade NAT.

  1. Run Tailscale on the NAS (UGOS app or a Docker container) and approve it as a subnet router for 10.0.30.0/24 (servers only). Add 10.0.50.0/24 only if you want raw camera access from outside.
  2. Install the Tailscale app on your phone and laptop. Sign in with an account that has MFA.
  3. In the admin console, set split DNS: queries for home.<yourdomain> go to AdGuard at 10.0.30.10. Then https://jellyfin.home.<yourdomain> works the same at home and away, using the wildcard certificate you already set up in Nginx Proxy Manager.
  4. Write an access policy (ACL) in Tailscale so only your own devices reach the subnet. Add family members later with narrower rules, for example Jellyfin only.
  5. Optional: make the NAS an exit node, so traffic from public Wi-Fi goes through your home connection.
Turn off UGREEN's own remote-access relay (UGREENlink) and UPnP on the router once Tailscale works. Every remote path you don't use is one less thing to keep patched.
Client apps

Publishing apps to external clients

Clients open https://real-estate.mydomain.com and https://health.mydomain.com with no VPN and nothing to install. The apps run in Docker on the Linux box in the DMZ, and Cloudflare Tunnel carries the traffic in.

Public addressGoes toAppLogin in front
real-estate.mydomain.comhttp://real-estate:8080real-estate-ptyOptional (Cloudflare Access)
health.mydomain.comhttp://health:8000Health appOptional (Cloudflare Access)

How it works

  1. A cloudflared container on the Linux box opens an outbound connection to Cloudflare. The router doesn't need port forwarding, your home IP stays hidden, and it works behind carrier-grade NAT.
  2. In the Cloudflare dashboard (Zero Trust → Networks → Tunnels) you add a public hostname for each app. Cloudflare creates the DNS record and the HTTPS certificate automatically.
  3. A client's browser connects to Cloudflare. Cloudflare sends the request down the tunnel, and cloudflared hands it to the right container.

Docker Compose on the Linux box

The apps don't publish any ports on the host. Only cloudflared can reach them, over a private Docker network.

services:
  cloudflared:
    image: cloudflare/cloudflared:latest   # pin a specific version once it works
    command: tunnel --no-autoupdate run
    environment:
      - TUNNEL_TOKEN=${TUNNEL_TOKEN}       # from the Cloudflare dashboard, kept in .env
    restart: unless-stopped
    networks: [public]

  real-estate:
    image: real-estate-pty:latest
    expose: ["8080"]                       # reachable by cloudflared, not by the LAN
    restart: unless-stopped
    networks: [public]

  health:
    image: health-app:latest
    expose: ["8000"]
    restart: unless-stopped
    networks: [public]

networks:
  public: {}

One domain, two kinds of names

  • Public names (real-estate., health.) live in Cloudflare DNS and point at the tunnel. Anyone can resolve them.
  • Private names (*.home.mydomain.com) live only in AdGuard at home and in Tailscale split DNS. They never appear in public DNS.
  • Buy the domain anywhere, but move its DNS to Cloudflare (the free plan is enough). The tunnel needs that, and NPM's wildcard certificate already uses it.

Before you give clients the link

  • Run production servers, not development ones: gunicorn or uvicorn instead of runserver or npm run dev, with debug mode off.
  • Tell the apps their public name. Set allowed hosts and CSRF trusted origins to the new hostnames, and trust the X-Forwarded-Proto header so the apps know they're behind HTTPS.
  • Decide who may see each app. If only known clients should get in, put Cloudflare Access in front: clients enter their email and get a one-time code. It's free for up to 50 users. If the apps are public websites, turn on Cloudflare's rate limiting and bot protection instead.
  • Back up the app databases. The NAS pulls nightly dumps from the Linux box over SSH.
Why not forward port 443 to Nginx Proxy Manager instead? That works, but it publishes your home IP, invites constant scanning, and breaks if your ISP uses carrier-grade NAT. The tunnel avoids all three. NPM stays inside for the *.home names.
100 MB limit per request. On Cloudflare's free plan, anything a browser sends to your app in a single request must be under 100 MB. In practice that means file uploads: one photo, a few PDFs or a short video are fine, but a single 300 MB video upload fails with error 413. Normal browsing, forms and downloads aren't affected, and there's no monthly total. If an app needs bigger uploads, upload in chunks (each under 100 MB) or do the large uploads yourself over Tailscale, which doesn't go through Cloudflare.

RAID isn't a backup. It covers a dead disk. It doesn't cover deleted files, ransomware, a failed NAS, theft or fire. Snapshots cover the first two. The USB drive and the cloud copy (Backblaze B2 or similar, about $6/TB/month) cover the rest.

Security baseline

Rules that apply everywhere

  • No inbound ports on the router. Turn UPnP off. Tailscale is the only way in for you. Cloudflare Tunnel is the only way in for clients, and it reaches only the DMZ.
  • Public apps stay in the DMZ. Never publish a NAS service or Home Assistant through the tunnel. Use Tailscale for those.
  • MFA everywhere it exists: the Tailscale identity, the UniFi account, the NAS admin and the Home Assistant admin.
  • Admin interfaces (NAS UI, NPM :81, the gateway) are reachable only from Trusted and Tailscale.
  • Separate accounts: one admin for management, a normal user for everyday file access, and app-specific users for shares.
  • Updates: turn on automatic security updates for UGOS and UniFi. Update Docker images monthly, with snapshots before.
  • Secrets (Cloudflare token, Tailscale keys) stay in .env files that are git-ignored, as this repo already does.
  • Test restores every quarter. A backup you haven't restored from is a guess.
Open questions

Decisions still to make

These change the parts list or the layout. Answers can go into the next version of this doc.

Can the ISP modem go into bridge mode?If not, the new gateway sits behind it (double NAT). That's fine for Tailscale, but harder to troubleshoot.
Can you run Ethernet to where the two access points will go?PoE APs need a cable each. If not, UniFi APs can mesh wirelessly, with some speed loss.
How many cameras, and are any outdoors?This sizes the PoE budget, the surveillance quota and whether Frigate needs a Coral accelerator.
UniFi or TP-Link Omada?UniFi is more polished. Omada costs about 30% less for the same VLAN features.
Which domain will you buy?The doc uses mydomain.com as a placeholder. Its DNS must be on Cloudflare for both the tunnel and NPM's wildcard certificate.
Should clients log in before they see the apps?If the real-estate and health apps are for specific clients, put Cloudflare Access in front. If they're public websites, leave them open but turn on rate limiting. A health app may hold sensitive personal data, which points toward Access.
Will anyone besides you need access to home services?That decides the Tailscale ACLs, for example family members who only get Jellyfin.
